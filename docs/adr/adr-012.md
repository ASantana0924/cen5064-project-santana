# ADR-012: Format the verification report as Markdown in the Presentation tier

**Date:** 2026-11-22
**Status:** accepted

## Context

UC-18 (#61) exports one task's verification record as a file someone can
keep, attach to a pull request, or hand to a reviewer. The file holds the
task details, requirements, acceptance criteria, each check with its evidence
or notes, test runs, every artifact version, approvals, and the audit
history. The issue asks the Service tier to gather the data and the
Presentation tier to format it. The questions were which format to use, and
where to build the file.

## Decision

`ReportService` loads the task and returns a `VerificationReport`, a record
holding copies of the task's values and lists plus the time the report was
made, from an injected `Clock`. It never saves the task. In the Presentation
tier, `VerificationReportMarkdown` turns the report into Markdown, and
`ReportController` serves it at `GET /api/tasks/{id}/report` as
`text/markdown` with a `Content-Disposition` attachment name made from the
title and the date. Text that developers typed is escaped so it shows as
written, prompts and code go in fences longer than any backticks inside them,
and times are in UTC. The frontend fetches the file and saves it under the
server's name.

## Alternatives considered

**PDF or HTML.** Better looking when printed, but a PDF needs a rendering
library and fonts, and an HTML file needs styles to read well. Markdown reads
well as plain text, renders on GitHub, and diffs cleanly in a repository.

**Build the file in the React app.** The data is already there, but a report
should be the same however it is fetched, including with `curl` or from a
script, and the server is where the full record lives.

**Pass the `Task` to the formatter.** Less code, but the formatter could then
call methods that change the task. The record is read-only by design.

## Consequences

Anyone can download a report with the API alone, and the format is tested
without the web layer. The cost is a second place that names statuses, checks,
and audit events for people, next to `frontend/src/lib/labels.ts`, so a new
value must be added to both. Every artifact version is included in full, which
suits artifacts of a few hundred lines but makes long histories long. Times
are in UTC because the server does not know the reader's time zone.
