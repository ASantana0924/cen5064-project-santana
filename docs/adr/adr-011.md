# ADR-011: Compute artifact diffs in the frontend with jsdiff

**Date:** 2026-11-21
**Status:** accepted

## Context

UC-17 (#60) lets a developer pick two artifact versions of a task and see
what changed in the AI tool, the prompt, and the code. The API already
returns the version list and each version in full, and a recorded version
never changes (ADR-007), so the frontend can cache every version for good.
Code needs a line diff that keeps indentation, and a prompt is prose, so it
needs a word diff: in a line diff, one changed word marks the whole
paragraph as changed. The question was where to compute the diff, and with
which library.

## Decision

The React app computes the diff in the browser from the two versions it
loads, using jsdiff (the `diff` package, version 9). Code uses `diffLines`,
which ignores Windows line endings and a missing final newline but counts
indentation, and the prompt uses `diffWordsWithSpace`. Our own `CodeDiff` and
`TextDiff` components render the result: one unified column with both line
numbers, + and − markers, and `ins`/`del` elements with screen reader labels.
The page lives at `/tasks/:id/artifacts/compare?from=&to=` and is loaded on
demand. The backend and the API do not change.

## Alternatives considered

**A backend endpoint (`GET .../artifacts/compare`) using java-diff-utils.**
It would add a controller, DTOs, and tests only to reformat data the client
already has, and each new pair of versions would cost a request. The diff is
a display concern, so it belongs in the Presentation tier.

**`react-diff-viewer-continued`.** A ready-made side-by-side viewer, but it
brings in Emotion CSS-in-JS and its own look, which does not match the
Tailwind and shadcn/ui components. It is built on jsdiff anyway.

**`diff-match-patch`.** It diffs characters, has no helper for line diffs,
and has had no release since 2020.

**A side-by-side layout.** Familiar from code review tools, but it needs
twice the width, and the unified layout also works on a phone.

## Consequences

Comparing needs no new endpoint, and picking another pair of cached versions
sends no request. The diff library and the page are a separate 18 kB file
(6 kB gzipped) that is downloaded only when someone compares. The whole code
is shown, which suits artifacts of a few hundred lines. I would revisit this
if artifacts grew to thousands of lines: collapsing long unchanged runs, or
computing the diff in a web worker or on the server. A server-side report
(#61) would need its own diff code.
