# ADR-001: Use Java 21 with Spring Boot for the technology stack

**Date:** 2026-09-28
**Status:** accepted

## Context

VerifAI needs a four-tier system (Presentation, Service, Domain, Data) with
one relational database, business rules that are easy to unit test, and a
build that my partner and instructor can run from a clean clone on conference
days. We have one semester, so the stack should give us persistence, web
pages, and testing without much setup. Both of us know Java, and the course
emphasizes layered design, which Spring's conventions support directly.

## Decision

Use Java 21 and Maven with Spring Boot. The Data tier uses Spring Data JPA
(Hibernate) with Flyway migrations against PostgreSQL, run in Docker Compose.
Tests use an in-memory H2 database. The Presentation tier uses Spring MVC with
server-rendered Thymeleaf templates. Tests use JUnit 5, with Mockito and
Spring Boot Test where needed.

Domain classes stay plain Java with no framework annotations. The Data tier
has its own JPA entity classes and maps them to and from Domain objects.

## Alternatives considered

**Python with FastAPI and a React frontend.** FastAPI is quick to start and
React gives a richer UI. We rejected it because it means two languages, two
build tools, and a separate frontend project to run and deploy, which adds
setup risk on conference days. It also splits our time between UI work and
the approval and reset rules, which are the core of the project. We would
only revisit it if the team turned out to be much stronger in Python than
Java.

## Consequences

Spring Boot gives us dependency injection, transactions, persistence, and
web pages from one Maven build, and `mvn verify` runs the whole test suite in
CI. H2 keeps tests fast and free of Docker, but it can behave differently from
PostgreSQL, so Flyway migrations should be checked against PostgreSQL before
merging.

Keeping annotations out of the Domain classes means the business rules can be
tested with plain JUnit, and the Domain tier does not depend on Spring or JPA.
The cost is a second set of entity classes and mapping code in the Data tier,
which must be updated whenever a Domain class changes. If that mapping becomes
too much work for the semester, we will annotate the Domain classes with JPA
directly and record that change in a new ADR that supersedes this part.

Thymeleaf keeps the UI simple but limits interactivity. REST controllers can
be added later if we need a separate frontend.
