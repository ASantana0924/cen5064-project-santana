# ADR-002: Use a React and TypeScript single page app over a JSON REST API

**Date:** 2026-10-11
**Status:** accepted

## Context

ADR-001 chose server-rendered Thymeleaf pages. Once the domain and services
were built, the UI became the main remaining risk: reviewers judge the project
by how it feels to use, and the workflow (checks, approval counts, version
history, audit timeline) needs an interactive screen. Thymeleaf pages reload on
every action and would need hand-written JavaScript to feel modern. I already
know React, so the extra setup is small for me.

## Decision

The Presentation tier has two parts. Spring `@RestController` classes under
`/api` take and return DTOs (Java records) and return JSON errors as
`{status, error, message}`. A React and TypeScript single page app, built with
Vite in `frontend/`, calls that API. Business rules stay in the Domain; the API
returns domain-computed flags such as `canApprove` so the frontend never
decides a rule. In development, Vite proxies `/api` to port 8080, so no CORS
setup is needed.

## Alternatives considered

**Thymeleaf with Bootstrap.** One build and one process, but limited
interactivity and a dated look for this kind of workflow.

**Next.js.** Its main benefit is server-side rendering, which this app does
not need. A Vite single page app is simpler to build, test, and run.

## Consequences

The UI can be as polished as a modern web app, and the REST API is testable on
its own. The cost is a second build (npm), a second process during
development, and a frontend CI job. "How to run" must cover both, which adds
risk on review days. The Thymeleaf page from #50 is removed in #52.
